# Alpha V2 negative transaction paths

`TestV2NegativeTransactionPaths` uses deterministic test keys, Alpha's real TxDecoder, the installed application AnteHandler, and an Ante cache context at height 105. No node, keyring, middleware, Keycloak, or network is used. Successful Ante writes are applied to the test cache; rejected Ante writes are discarded. The harness does **not** execute MsgSend or commit a block. It therefore proves rejection before Msg execution and unchanged test balances/sequence, not live FinalizeBlock persistence.

The negative tests check sender/receiver `token` balances, sender `stake` fee balance, account sequence, and absence of the V2 success event after each rejection. Available V1 CURRENT grants in structural, duplicate, expired, and stale-certificate cases prove no V2-to-V1 fallback. The exact replay is **not** rejected by the certificate verifier: the SDK rejects its stale signer sequence first.
